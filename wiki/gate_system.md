# 大门系统开发文档

## 1. 概述
`The Maze Runner` 插件中的大门系统（Gate System）经过了高度定制化开发，旨在提供电影级的视觉体验和服务器端的极致性能。本系统抛弃了传统的方块替换（FallingBlock）方案，转而采用 Minecraft 1.20+ 引入的 `BlockDisplay` 实体技术，支持平滑变换、超远视距渲染和复杂的动画逻辑。

## 2. 核心功能
*   **双扇门结构**：每个大门由左（Left）右（Right）两个区域组成，分别向反方向滑动。
*   **自适应轴向**：系统能自动根据选区形状判断门是沿 X 轴还是 Z 轴滑动，无需人工介入。
*   **BlockDisplay 渲染**：利用显示实体的 `Transformation` 插值动画，实现无卡顿的开关门效果。
*   **动静分离**：
    *   **关闭状态**：大门由真实的服务器方块组成，拥有完整的物理碰撞体积和防爆属性。
    *   **开启状态**：真实方块消失，变为 `BlockDisplay` 实体并滑入墙体。若配置允许，实体随后会被清理以释放资源；关门时自动重生。
*   **运行时热编辑**：无需重启服务器或重载配置，即可通过指令实时修改大门的所有参数。

## 3. 详细参数说明

系统提供了丰富的参数供管理员调整，以适应不同的服务器性能需求和游戏玩法。

### 3.1 基础参数
*   **名称 (Name)**：大门的唯一标识符。
*   **滑动距离 (Slide Distance)**：门扇向两侧移动的格数。
    *   设为 `<= 0` 时，系统会自动计算门扇自身的宽度作为移动距离（完全开启）。
    *   设为具体数值（如 10.0）时，将强制移动该距离。
*   **动画时长 (Duration)**：开关门动作持续的时间（秒）。
    *   系统会自动保证至少 1 tick 的时长，避免除零错误或瞬移卡顿。

### 3.2 移动模式 (MoveMode)
决定大门动画的底层实现技术。

*   **`TRANSFORM` (默认推荐)**
    *   **原理**：实体坐标保持不变，仅修改 `Transformation` 矩阵的 Translation 分量。
    *   **优点**：
        *   **极度流畅**：利用客户端插值，动画丝滑无卡顿。
        *   **低负载**：服务端只需发送一次包。
        *   **支持长时间动画**：无时长限制。
    *   **缺点**：存在客户端剔除问题（大门移出原点视口时可能消失，需配合 `cull` 参数调整）。

*   **`TELEPORT`**
    *   **原理**：利用 `display.teleport()` 并在客户端进行位置插值。
    *   **限制**：**最大动画时长被限制为 59 ticks (约 3 秒)**。若配置时长超过此值，视觉动画会在 3 秒内完成，但逻辑大门会在完整时长后开启。这是受限于 Minecraft 协议。
    *   **优点**：抗剔除能力强，适合超大尺寸且动画时间较短的大门。

### 3.3 安全模式 (SafeMode)
决定关门时的安全保护策略。

*   **`NONE` (默认)**
    *   不做任何处理，直接恢复方块。
    *   **风险**：若玩家站在门下，会被方块卡且窒息。
*   **`BARRIER` (阻挡)**
    *   在关门动画的**最后阶段**（实体化前夕），将门洞区域的空气替换为隐形屏障（Barrier）。
    *   **效果**：防止玩家在最后一刻冲入并将被卡住的区域。
*   **`PUSH` (推离 - 气浪特效)**
    *   **原理**：检测门洞区域内的所有生物（含玩家）。
    *   **效果**：
        *   **气浪冲击**：施加一个垂直于大门方向的微小反向推力，模拟气流将实体推开。
        *   **视听特效**：伴随轰鸣声、撞击声，以及底部扬起的尘土和碎石粒子效果。
        *   **安全保护**：防止玩家被夹在方块中。

### 3.4 性能与渲染优化参数

*   **保持常驻 (`KeepOpen`)**
    *   `true`：大门开启后，`BlockDisplay` 实体保留在原地。这意味着关门时无需重新生成实体，动画极度流畅，但会持续占用客户端渲染资源和服务端实体数。
    *   `false` (默认)：大门完全开启后，**销毁所有实体**。关门时再重新生成。极大节省资源，但关门启动时可能有 1 tick 的生成延迟。

*   **仅渲染外壳 (`ShellOnly`)**
    *   `true`：对于实心的大门（例如厚度为 5 的石墙），系统**只生成最外层一圈**的显示实体，内部方块只处理逻辑但不渲染。
    *   `false` (默认)：渲染每一个方块。
    *   **效果**：对于厚重的大门，开启此选项可减少 **60%-80%** 的实体数量，显著提升客户端 FPS。

*   **视距 (`ViewRange`)**
    *   控制客户端渲染该实体的最大距离（默认 12.0，约 192 格）。
    *   对于超大型地标建筑，可适当调大此值。

*   **裁剪框 (`Culling`)**
    *   仅在 `TRANSFORM` 模式下生效。手动设置实体的宽/高，强行扩大客户端的视锥体剔除判定框，防止实体消失。

### 3.5 轴向锁定 (Axis)
*   **`AUTO`**：根据选区长宽比自动判断（99% 准确）。
*   **`X` / `Z`**：强制锁定滑动方向。

## 4. 指令系统
所有指令均挂载于 `/gate` 下。

| 子命令 | 权限 | 参数 | 描述 |
| :--- | :--- | :--- | :--- |
| `wand` | `tmr.gate.wand` | 无 | 获取选区魔杖（木斧）。 |
| `select` | `tmr.gate.select` | `<left/right>` | 将当前 WorldEdit/魔杖选区保存为大门的左/右扇区。 |
| `create` | `tmr.gate.admin` | `<name> [dist] [time]` | 创建大门。`dist`为滑动距离，`time`为时长(秒)。 |
| `open` | `tmr.gate.control` | `<name>` | 开启指定大门。 |
| `close` | `tmr.gate.control` | `<name>` | 关闭指定大门。 |
| `edit` | `tmr.gate.admin` | `<name> <prop> <val>` | **实时编辑大门属性**（见下表）。 |

### 4.1 `/gate edit` 属性列表

| 属性 (`prop`) | 值 (`val`) | 示例 | 说明 |
| :--- | :--- | :--- | :--- |
| `axis` | `AUTO`, `X`, `Z` | `/gate edit G1 axis X` | 锁定滑动轴向。 |
| `safemode` | `NONE`, `BARRIER`, `PUSH` | `/gate edit G1 safemode PUSH` | 设置安全防夹模式。 |
| `movemode` | `TELEPORT`, `TRANSFORM` | `/gate edit G1 movemode TELEPORT` | 切换动画底层实现。 |
| `keepopen` | `true`, `false` | `/gate edit G1 keepopen false` | 是否在开门后保留实体。 |
| `shellonly` | `true`, `false` | `/gate edit G1 shellonly true` | 是否开启空心外壳优化。 |
| `viewrange` | 浮点数 (如 16.0) | `/gate edit G1 viewrange 50` | 设置实体可视距离系数。 |
| `cull` | `宽 高` (如 10 10) | `/gate edit G1 cull 50 20` | 设置裁剪框（仅 TRANSFORM 需用）。 |

## 5. 开发接口
开发者可通过 `GateManager` 访问 API。

```java
// 获取大门实例
Gate gate = gateManager.getGate("NorthGate");

// API 修改配置 (支持热重载)
gate.setMoveMode(Gate.MoveMode.TELEPORT);
gate.setSafeMode(Gate.SafeMode.PUSH); 
gate.setShellOnly(true); // 开启极致优化

// 获取所有大门名称
Collection<String> names = gateManager.getGateNames();
```
